# LeadFlow

Рабочее пространство для поиска организаций, AI-анализа, приватных демо-сайтов и CRM. Данные каждого пространства отделены. Публичный телефон или email с карты не считается согласием на рекламу.

## Локально

Нужны Node.js 22 и PostgreSQL. Redis необязателен: очередь задач хранится в базе, Redis только ускоряет выдачу.

```bash
copy .env.example .env
```

Заполните `DATABASE_URL`, `AUTH_SECRET` (не короче 32 символов) и `ENCRYPTION_KEY` (не короче 32 символов). Остальные ключи можно оставить пустыми и вписать позже в разделе «Интеграции».

```bash
npm install
npx prisma migrate deploy
npm run dev:all
```

`dev:all` поднимает сайт и обработчик. Без обработчика поиск можно создать, но долгие задачи AI, сайтов и кампаний будут ждать. На обзоре появится предупреждение, если обработчик молчит дольше 30 секунд.

Первый открытый адрес — `/register`. Он создаёт пространство и владельца. Если `ALLOW_REGISTRATION=false`, регистрация закрывается после появления первого пользователя.

## Переменные

Обязательны для запуска: `DATABASE_URL`, `AUTH_SECRET`, `ENCRYPTION_KEY`.

Ключи Parser, Studio, OpenRouter, почты, Telegram, WhatsApp, SMS и хранилища можно задать в окружении или в интерфейсе. Значение из базы перекрывает окружение. Секрет после сохранения целиком не возвращается. Интеграция не считается подключённой, пока проверка не прошла.

`APP_URL` нужен для ссылки приглашения. Агент вызывает DeepSeek V4 Flash, анализ — GLM 5.3 Flash, черновики — Gemma 4 31B. Имя вне этого списка заменяется моделью задачи.

## Docker

На сервере приложение слушает только `127.0.0.1:3100`. Postgres и Redis наружу не публикуются.

```bash
# в .env задайте POSTGRES_PASSWORD, AUTH_SECRET, ENCRYPTION_KEY и остальные ключи
docker compose up -d --build
```

Миграции применяет только контейнер `app` (`RUN_MIGRATIONS=1`). Обработчик — отдельный контейнер `worker`.

Пример nginx для одного имени лежит в `deploy/nginx-leadflow.conf`. Его нужно добавить новым файлом сайта. Существующие виртуальные хосты и их сертификаты этот файл не меняет. Сертификат для `leadflow.siteaccess.ru` выпускается отдельно, только на это имя, после того как известны пользователь SSH и текущая схема nginx.

## Правила продукта

- Поиск идёт в Parser API. Поле региона хранится у вас и в парсер не отправляется: в его контракте такого поля нет.
- Одинаковый поиск за сутки не запускается повторно, пока это не подтверждено отдельно.
- AI пишет только то, что подтверждено фактами. Неизвестное остаётся неизвестным. Некорректный JSON не сохраняется как отчёт.
- Стоимость записывается, только если API её вернул.
- Демо-сайт остаётся непубличным, пока публикацию отдельно не подтвердят. Критичные замечания QA публикацию блокируют.
- Сообщение уходит после одобрения и указания основания: согласие, договор или иное основание с пояснением. WhatsApp требует согласия и имени шаблона.
- Кампания не стартует без подтверждённого основания. Автоматизация не умеет отправлять, публиковать и запускать кампании.
- Примеры в настройках помечены как демо, не входят в показатели и не вызывают Studio и OpenRouter.

## Копии базы

```bash
docker compose exec postgres pg_dump -U leadflow leadflow > leadflow.sql
```

Секреты лежат в базе в зашифрованном виде. Без того же `ENCRYPTION_KEY` они не читаются, поэтому ключ шифрования храните отдельно от дампа.
